# Стемік CRM — демоверсія для захисту

Базова версія CRM STEM-студії «Стемік»: робоче місце **адміністратора студії**.
Сайт — це статичні файли (HTML + CSS + JS без збирання). Він працює з базою даних
у **навчальному проєкті Supabase** через REST API.

| Розділ | Що вміє |
|---|---|
| Вхід | перевірка підключення до Supabase (ping) і вхід працівника (Supabase Auth) |
| Огляд дня | заняття на обрану дату, показники студії (абонементи, борги) |
| Журнал заняття | відмітка «був / відсутній / поважна» з оплатою: картка, готівка, абонемент (списання), борг |
| Учні | **пошуковий запит 1**: пошук за ПІБ, батьками або частиною телефону; картка учня; новий учень із батьками |
| Розклад | **пошуковий запит 2**: заняття за період з фільтром курсу й викладача; нове заняття |
| Абонементи | стан абонементів з телефонами батьків; продаж абонемента |
| Боржники | **пошуковий запит 3**: присутні без оплати, сума боргу, телефони батьків |

> ⚠️ Використовуйте **окремий навчальний проєкт Supabase**, а не робочий проєкт студії:
> скрипт `01_schema.sql` видаляє й створює схему `stemik` заново.

## Крок 1. Створити навчальний проєкт Supabase

1. Увійдіть на <https://supabase.com/dashboard> → **New project**.
2. Назва — наприклад `stemik-training`, регіон — найближчий (Central EU / Frankfurt), пароль бази — будь-який (збережіть).
3. Дочекайтеся, поки проєкт створиться (1–2 хв).

Якщо навчальний проєкт уже є (з лабораторних робіт) — можна використати його: скрипти
перестворять лише схему `stemik` і функції `crm_*`, таблиці схеми `public` не чіпаються.

## Крок 2. Створити базу даних (SQL Editor)

У проєкті: **SQL Editor → New query**. По черзі відкрийте файли з папки `sql/`,
скопіюйте вміст у редактор і натисніть **Run** (Ctrl + Enter):

| № | Файл | Очікуваний результат |
|---|---|---|
| 1 | `01_schema.sql` | `Success. No rows returned` |
| 2 | `02_data.sql` | результат `setval` (кілька чисел) — дані завантажено |
| 3 | `03_views.sql` | `Success` |
| 4 | `04_crm_api.sql` | `Success` |

Перевірка — виконайте в SQL Editor:

```sql
select public.crm_ping();
```

Має повернутися JSON з `"tables": 18`, `"students": 52`, `"lessons": 496`.

> Файл `02_data.sql` великий (≈ 650 КБ). Якщо редактор не приймає його цілком,
> виконайте через `psql` (рядок підключення: **Connect → Connection string → URI**):
> `psql "postgresql://postgres:ПАРОЛЬ@db.XXXX.supabase.co:5432/postgres" -f sql/02_data.sql`

## Крок 3. Створити користувача-адміністратора

1. **Authentication → Users → Add user → Create new user**.
2. Вкажіть e-mail і пароль (наприклад `admin@stemik.test` / свій пароль), увімкніть **Auto Confirm User** → **Create user**.
3. **Обов’язково вимкніть самостійну реєстрацію**: **Authentication → Sign In / Providers →
   Allow new users to sign up → вимкнути → Save**. Інакше будь-хто зможе зареєструватися й отримати доступ до даних.

Необов’язково: щоб відмітки й продажі записувалися від вашого імені, додайте себе як працівника
(e-mail — той самий, що в користувача):

```sql
insert into stemik.employee (email, last_name, first_name, role)
values ('admin@stemik.test', 'Прізвище', 'Ім’я', 'admin');
```

Без цього дії записуються від імені першого активного адміністратора з даних («Адмін 01»).

## Крок 4. Підключити сайт до проєкту

1. **Project Settings → API Keys** (або **Data API**): скопіюйте
   - **Project URL** — `https://XXXX.supabase.co`;
   - ключ **anon public** (або **publishable**, `sb_publishable_…`).
2. Відкрийте `config.js` і впишіть:

```js
window.CRM_CONFIG = {
  url: 'https://XXXX.supabase.co',
  anonKey: 'eyJhbGciOi…',   // або 'sb_publishable_…'
};
```

> ❌ Ніколи не вписуйте ключ **service_role** / **secret**: він обходить усі обмеження доступу.
> Ключ anon публікувати можна — без входу він відкриває лише функцію `crm_ping()`.

## Крок 5. Запустити сайт

Будь-який із варіантів:

- **Найпростіше:** двічі клацнути `index.html` — відкриється в браузері (Chrome, Edge, Firefox).
- **Локальний сервер** (рекомендовано, якщо браузер блокує файли):
  ```bash
  cd stemik-crm-demo
  python -m http.server 8000
  ```
  і відкрити <http://localhost:8000>.
- **GitHub Pages:** завантажити папку в репозиторій → Settings → Pages → гілка → відкрити адресу сайту.

На екрані входу блок **«Підключення до бази даних»** має показати зелену крапку
**«Підключено»**, час відповіді, версію PostgreSQL і кількість рядків. Це і є «пінг» проєкту Supabase.
Далі увійдіть e-mailом і паролем з кроку 3.

## Сценарій демонстрації на захисті (≈ 5 хв)

1. **Екран входу** — показати «Підключено»: сайт звертається до бази в Supabase (`crm_ping`).
2. **Увійти** → **Огляд дня**: кнопками «день →» перейти на суботу 21.11.2026 — 5 занять, показники студії.
3. Натиснути заняття → **журнал**: учню з абонементом обрати оплату «абонемент» → «був» —
   внизу з’явиться новий залишок; іншому — «картка»; потім одному — «відсутній»
   (заняття повертається на абонемент).
4. **Учні** → ввести `010` (пошуковий запит 1) → розгорнути «Пошуковий запит 1: SQL» →
   відкрити картку учня.
5. **Розклад** → курс «3D Tinkercad FIRST» (пошуковий запит 2).
6. **Боржники** → «не менше 2» (пошуковий запит 3).
7. **+ Новий учень** з телефоном батьків → **+ Продати абонемент** → у розкладі
   **+ Заняття** з цим учнем → відмітити його «був · абонемент».

Ті самі три запити наживо в **SQL Editor** — файл `sql/05_search_queries.sql`:
виділити запит, Run, змінити параметр у блоці `WITH params AS (…)`, Run ще раз.

## Як повернути дані до початкового стану

Повторно виконати `01_schema.sql`, `02_data.sql`, `03_views.sql`, `04_crm_api.sql`
(і, за потреби, `insert into stemik.employee …` з кроку 3).

## Як це влаштовано

```
Браузер (index.html, app.js)
   │  POST /auth/v1/token             — вхід (Supabase Auth) → токен сесії
   │  POST /rest/v1/rpc/crm_<функція> — виклик функції бази з токеном
   ▼
Supabase (PostgREST) ─► public.crm_*  (SECURITY DEFINER, search_path = stemik)
                           ▼
                        схема stemik: 18 таблиць, 2 представлення
```

- Схема `stemik` **не відкрита** в REST API: браузер не може прочитати чи змінити таблиці напряму.
- Без входу (роль `anon`) доступна лише `crm_ping()`; решта функцій — тільки для ролі `authenticated`.
- Цілісність забезпечує сама база: первинні й зовнішні ключі, `CHECK`, `UNIQUE`.
  Списання з абонемента блокує рядок (`SELECT … FOR UPDATE`), а повторна відмітка спершу повертає списане заняття.

| Функція | Що робить |
|---|---|
| `crm_ping()` | перевірка підключення (без входу) |
| `crm_refs()` | курси, викладачі, поточний працівник |
| `crm_dashboard(p_date)` | огляд дня |
| `crm_students(p_q, p_active_only)` | **пошуковий запит 1** |
| `crm_student(p_id)`, `crm_student_save(…)` | картка учня, створення / зміна з батьками |
| `crm_lessons(p_from, p_to, p_course, p_teacher)` | **пошуковий запит 2** |
| `crm_lesson(p_id)`, `crm_lesson_create(…)`, `crm_lesson_add_student(…)`, `crm_lesson_complete(…)` | журнал і заняття |
| `crm_mark(p_lesson, p_student, p_status, p_payment)` | відмітка з оплатою |
| `crm_subscriptions(p_status)`, `crm_subscription_sell(…)` | абонементи |
| `crm_debtors(p_min)` | **пошуковий запит 3** |

## Якщо щось не працює

| Повідомлення | Що зробити |
|---|---|
| «Не заповнено config.js» | вписати `url` і `anonKey` (крок 4) |
| «Немає зв’язку з Supabase» | перевірити `url` у config.js та інтернет; проєкт на безкоштовному тарифі міг «заснути» — відкрийте його в Dashboard і натисніть **Restore** |
| «Функцію crm_… не знайдено» | виконати `04_crm_api.sql` (крок 2) |
| «Invalid API key» | скопійовано не той ключ: потрібен anon / publishable |
| «Невірний e-mail або пароль» | перевірити користувача в Authentication → Users (Auto Confirm) |
| «permission denied for function …» на екрані входу | так і має бути: без входу доступний лише ping |
| «Сесія завершилась» | увійти ще раз (сесія Supabase — 1 година, оновлюється автоматично) |
