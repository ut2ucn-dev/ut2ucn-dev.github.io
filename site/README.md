# Стемік · CRM студії — розгортання сайту й бази даних

Сайт — робоче місце працівника STEM-студії «Стемік» в оформленні основного застосунку студії
(бічна панель, кнопки, картки, журнал заняття, світла й темна тема). Це урізана версія повного
застосунку: увімкнено лише те, що вже реалізовано в базі на поточному етапі.

| Розділ сайту | Що вміє | Де в базі |
|---|---|---|
| **Огляд дня** | заняття дня, показники студії, найближче заняття | `crm_dashboard`, представлення `v_schedule` |
| **Розклад** | тиждень за днями, фільтр курсу й викладача; нове заняття, зміна, видалення | `crm_lessons`, `crm_lesson_create / _update / _delete` |
| **Журнал заняття** | «Був / Не був / ВПП», оплата карткою, готівкою, абонементом або в борг; запис учня на заняття | `crm_lesson`, `crm_mark`, `crm_lesson_add_student / _remove_student` |
| **Учні** | пошук за ім’ям, батьками, телефоном; картка з вкладками; новий учень із батьками; деактивація | `crm_students`, `crm_student`, `crm_student_save`, `crm_student_set_active` |
| **Абонементи** | стан, продаж, скасування | `crm_subscriptions`, `crm_subscription_sell / _cancel`, `v_subscription_status` |
| **Боржники** | присутні без оплати, сума боргу, телефони батьків | `crm_debtors` |
| **Звіти** | виручка за місяцями й частки способів оплати, по тижнях наростаючим, навантаження викладачів, курси, учні без майбутніх занять | `crm_report_*` |
| **Тарифи** | ціни занять, абонементів і оплата викладача — редагування | `crm_tariffs`, `crm_tariff_save` |

Поки **вимкнено** (буде на наступних етапах): черга 3D-друку, зарплата, керування викладачами,
кабінети батьків, фото.

## Крок 1. База даних (Supabase → проєкт Stemik_bd → SQL Editor)

Кожен файл: **SQL Editor → + New query → відкрити файл у Блокноті → Ctrl+A, Ctrl+C → вставити → Run**.
Текст беріть **з файлу**, а не з чату чи месенджера. На вікно про RLS відповідайте
**Run and enable RLS**: сайт працює через функції, на які RLS не впливає.

## Крок 2. Користувач для входу

Якщо ще не створено на МКР:

1. **Authentication → Users → Add user → Create new user** — e-mail, пароль, **Auto Confirm User**.
2. **Authentication → Sign In / Providers → Allow new users to sign up → вимкнути → Save**.

## Крок 3. Файли сайту на GitHub

Сайт замінює попередню версію CRM у корені репозиторію (`stemikprg.github.io`):

1. У репозиторії **замініть** файли `index.html`, `app.js`, `app.css` новими з архіву
   (**Add file → Upload files** → перетягнути → **Commit changes**; GitHub перезапише файли з тими самими іменами).
2. Файл **`config.js` не замінюйте** — у ньому вже ваші адреса й ключ (формат той самий).
   Якщо розгортаєте з нуля — впишіть у `config.js` **Project URL** і ключ **anon** / **publishable**
   (Project Settings → API Keys). Ключ `service_role` / `secret` туди не вписуйте.
3. Файл `search_sql.js` від МКР новому сайту не потрібен — його можна видалити.
4. За бажанням завантажте теку `sql/` — щоб викладач бачив скрипти в репозиторії.

За 1–2 хвилини (вкладка **Actions** → зелена галочка) сайт оновиться:
`https://skywalker345.github.io/stemikprg.github.io/` — оновіть сторінку з **Ctrl+F5**.

## Крок 4. Перевірка

1. Екран входу: блок «**База підключена**» з кількістю учнів і занять.
2. Увійти → **Огляд дня** → кнопкою «›» перейти на день із заняттями → натиснути заняття → журнал.
3. **Адміністрування → Звіти** — таблиці мають заповнитися; **Тарифи** — список цін.

Якщо звіти чи тарифи показують «У базі немає функції crm_…», не виконано `05_crm_api_v2.sql`.

## Що показувати на захисті ЛР2–ЛР4

Сайт — це продукт для студії; кожна лабораторна закладає в базу частину того, на чому він працює.

### ЛР2 · Модель даних у СУБД

У SQL Editor виконайте `sql/lr2/lr2_01_schema.sql`, потім `sql/lr2/lr2_02_seed.sql` —
схема `stemik_model` (18 таблиць, 52 CHECK, 102 тестові рядки) поруч із робочою, CRM не зачіпається.

- **Database → Schema Visualizer** → схема `stemik_model` — діаграма таблиць і зв’язків.
- Перевірка обмежень у SQL Editor (кожна команда — помилка з назвою обмеження, дані не змінюються):
  ```sql
  UPDATE stemik_model.tariff SET lesson_price = -100 WHERE tariff_id = 1;
  UPDATE stemik_model.lesson SET format = 'webinar'
   WHERE lesson_id = (SELECT min(lesson_id::text)::uuid FROM stemik_model.lesson);
  DELETE FROM stemik_model.course WHERE course_id = 1;
  ```
- На сайті ті самі обмеження захищають дані: новий учень із телефоном наявних батьків
  прив’язується до них (UNIQUE), відмітити можна лише записаного учня (складений FK).

### ЛР3 · Таблиці й дані засобами SQL

База сайту — це результат ЛР3: `01_schema.sql` (CREATE TABLE, 86 іменованих обмежень) і
`02_data_*.sql` (2480 рядків, перенесених із копії робочої бази `INSERT … SELECT`).
Операції зміни даних показуються на сайті:

| Оператор | Дія на сайті | Що відповідає база |
|---|---|---|
| `INSERT` | Учні → **+ Учень** (разом із батьками); Розклад → **+ Заняття**; Абонементи → **+ Абонемент** | новий рядок; батьки з тим самим телефоном не дублюються |
| `UPDATE` | Журнал → **Змінити**; Тарифи → змінити ціну → **Зберегти**; картка учня → **Деактивувати** | ціна вже проведених занять не змінюється — вона зафіксована в занятті |
| `DELETE … CASCADE` | Журнал заняття без відміток → **Видалити** | разом із заняттям видаляються записи учнів на нього |
| `RESTRICT` | Журнал заняття з відмітками → **Видалити** | відмова: заняття має історію оплат |

Скрипти `ALTER / UPDATE / DELETE / TRUNCATE / DROP` з протоколу (`docs/db-labs/lab3/sql/03…07`)
призначені для консолі `psql` (використовують `\timing`, `\echo` і навмисні помилки) — у SQL Editor
Supabase їх не виконують; результати наведено скриншотами в протоколі.

### ЛР4 · Запити

- **SQL Editor**: `sql/lr4/lr4_queries_supabase.sql` — 24 запити; виділіть один блок (від
  `SET search_path` до `;`) → **Run**.
- **Сайт → Адміністрування → Звіти** — ті самі прийоми в робочих звітах:

| Звіт на сайті | Запит ЛР4 | Конструкції |
|---|---|---|
| Виручка | 4.12, 4.24 | `GROUP BY`, `SUM() OVER (PARTITION BY …)` |
| По тижнях | 4.23 | `SUM(…) OVER (ORDER BY …)` — наростаючий підсумок |
| Викладачі | 4.13 | `WHERE` + `HAVING`, `COUNT(DISTINCT …)`, підзапит у `SELECT` |
| Курси | 4.14, 4.15, 4.17 | похідна таблиця у `FROM`, `FILTER`, скалярні підзапити |
| Випали з розкладу | 4.16 | корельовані `EXISTS` / `NOT EXISTS` |
| Розклад, Абонементи | 4.20, 4.21 | представлення `v_schedule`, `v_subscription_status` |
| Учні (пошук), Розклад, Боржники | пошукові запити МКР (`sql/queries/`) | `ILIKE`, `LEFT JOIN`, `GROUP BY … HAVING` |

## Якщо щось не працює

| Повідомлення | Що зробити |
|---|---|
| «Не заповнено config.js» | вписати `url` і `anonKey` (крок 3) |
| «Invalid API key» | адреса й ключ — з різних проєктів; ID в адресі має збігатися з Project Settings → General |
| «У базі немає функції crm_…» | виконати `sql/05_crm_api_v2.sql` (або всі файли варіанта Б) |
| «Невірний e-mail або пароль» | перевірити користувача в Authentication → Users (Auto Confirm) |
| «Заняття вже має відмітки відвідування…» | так і має бути: заняття з історією оплат не видаляється |
| сайт не оновився після завантаження | дочекатися зеленої галочки у вкладці Actions, оновити з Ctrl+F5 |
