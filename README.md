# Stemik · облік моделей — багатокористувацька версія

Ця версія розрахована на кількох викладачів із власними обліковками та одного
суперадміністратора, який бачить усіх користувачів і всі моделі.

**Важливо розуміти структуру:** GitHub (Pages) віддає лише статичні файли — він
не вміє зберігати спільну базу даних чи перевіряти паролі. Тому реальні
дані (користувачі, учні, заняття, фото) зберігаються в окремому безкоштовному
сервісі **Supabase** (хмарна Postgres-база + автентифікація). Файли з цієї
папки — це лише інтерфейс, який підключається до вашого власного
Supabase-проєкту.

## Що вміє кожна роль

- **Викладач (teacher)** — реєструється сам, веде свій список учнів (додає нових дітей), на кожному занятті прикріпляє фото роботи учня та позначає, що модель надрукована. Розклад занять викладач лише переглядає — створювати, редагувати чи видаляти заняття він не може.
- **Суперадміністратор (admin)** — бачить список усіх викладачів, для кожного окремо складає розклад занять (дата, тема, які учні присутні, повторення щотижня), і може переглядати (без редагування) список учнів і чергу друку будь-якого викладача.

Це розділення діє не лише в інтерфейсі, а й на рівні бази даних (RLS-політики) — навіть якщо викладач спробує обійти інтерфейс, база сама відхилить спробу створити чи змінити заняття.

## Якщо застосунок уже розгорнутий раніше

Якщо ви вже створювали Supabase-проєкт для попередньої версії — нічого
пересоздавати не треба. Просто відкрийте **SQL Editor** й ще раз повністю
виконайте оновлений **`schema.sql`** — він безпечно оновить лише права
доступу (тепер розклад редагує лише admin) і створить сховище для фото.
Дані, які вже є в базі, не постраждають. Після цього замініть файл
**`index.html`** на новий і не забудьте, що фото тепер завантажуються у
Supabase Storage, а не зберігаються прямо в базі (див. розділ нижче).

---

## Крок 1. Створіть проєкт Supabase (5 хвилин, безкоштовно)

1. Зайдіть на **supabase.com** → «Start your project» → увійдіть через GitHub.
2. Натисніть **New project**. Вкажіть будь-яку назву (наприклад `stemik-tracker`)
   і надійний пароль бази даних (збережіть його десь — знадобиться рідко).
3. Зачекайте ~1-2 хвилини, поки проєкт створюється.

## Крок 2. Створіть таблиці бази даних

1. У боковому меню Supabase відкрийте **SQL Editor** → **New query**.
2. Відкрийте файл **`schema.sql`** з цієї папки, скопіюйте весь вміст і
   вставте в редактор.
3. Натисніть **Run**. Має з'явитися «Success. No rows returned».

Це створить таблиці `profiles`, `students`, `lessons`, `works` і налаштує
правила доступу (кожен викладач бачить лише своє, адмін бачить усе).

## Крок 3. Вимкніть підтвердження email (щоб реєстрація працювала одразу)

За замовчуванням Supabase надсилає лист із підтвердженням при реєстрації.
Для невеликої студії простіше це вимкнути:

1. **Authentication** → **Providers** → **Email**.
2. Вимкніть перемикач **Confirm email**.
3. Збережіть.

*(Якщо залишите увімкненим — це теж працюватиме, просто кожен новий
викладач після реєстрації має підтвердити email за посиланням із листа,
перш ніж зможе увійти.)*

## Крок 4. Скопіюйте ключі підключення

1. **Project Settings** (значок шестерні) → **API**.
2. Скопіюйте два значення:
   - **Project URL**
   - **anon public** ключ (це публічний ключ, його можна тримати у відкритому
     коді на GitHub — саме для цього і потрібні правила доступу з кроку 2.
     НЕ використовуйте `service_role` ключ — той секретний).
3. Відкрийте файл **`config.js`** із цієї папки і вставте туди свої значення:

```js
window.SUPABASE_URL = "https://ваш-проєкт.supabase.co";
window.SUPABASE_ANON_KEY = "ваш-anon-ключ";
```

## Крок 5. Викладіть на GitHub

1. Створіть новий репозиторій на GitHub (можна приватний).
2. Завантажте туди файли **`index.html`** і **`config.js`** (саме ці два —
   `schema.sql` і цей README можна теж додати для історії, але для роботи
   сайту вони не потрібні).
3. **Settings** → **Pages** → Source: `Deploy from a branch` → оберіть
   гілку `main` і папку `/root` → Save.
4. За хвилину GitHub покаже посилання на сайт
   (`https://ваш-логін.github.io/назва-репозиторію/`).

## Крок 6. Зареєструйтесь і призначте себе суперадміном

1. Відкрийте отримане посилання, натисніть «Реєстрація», введіть свій email
   і пароль.
2. Поверніться в Supabase → **SQL Editor** → **New query**, виконайте
   (підставивши свій email):

```sql
update profiles set role = 'admin' where email = 'ваш@email.com';
```

3. Перезайдіть у застосунок — зверху бічної панелі з'явиться перемикач
   **«Мій кабінет» / «Адмін»**. У розділі «Адмін» видно всіх зареєстрованих
   викладачів, кількість їхніх учнів/занять/моделей на друk, і можна
   відкрити розклад (з можливістю редагування), учнів і чергу друку будь-кого.

Усі наступні викладачі просто заходять на те саме посилання й реєструються
самостійно — за замовчуванням отримують звичайну роль `teacher` і бачать
лише свої дані.

## Крок 7. Фото зберігаються у Supabase Storage

Крок 2 (`schema.sql`) уже автоматично створив потрібний бакет **`works-photos`**
і правила доступу — додатково нічого налаштовувати не треба. Фото стискаються
в браузері перед завантаженням (приблизно до 900px по довшій стороні), тож
займають небагато місця.

## Що з безпекою

- Паролі користувачів обробляє Supabase Auth (це справжня, а не декоративна
  автентифікація — на відміну від попередньої офлайн-версії).
- Rule-level security (RLS) у базі гарантує, що навіть якщо хтось відкриє
  консоль розробника, він технічно не зможе прочитати чужі дані через API —
  Postgres сам відхилить такий запит на рівні бази. Це стосується і спроби
  викладача створити чи змінити заняття — таку дію відхилить сама база, а
  не лише інтерфейс.
- `anon` ключ у `config.js` призначений бути публічним — це нормально й
  безпечно саме завдяки RLS-політикам з `schema.sql`.
- Фото у сховищі технічно доступні за прямим посиланням тому, хто його
  вгадає чи отримає (бакет публічний для читання — це потрібно, щоб фото
  показувались і в адмін-панелі). Самі посилання ніде не публікуються, крім
  бази даних, тож випадковий доступ малоймовірний, але це не приватне
  сховище в строгому сенсі.

## Обмеження поточної версії

- Безкоштовний тариф Supabase має ліміти (проєкт «засинає» після тривалої
  бездіяльності, обмежений обсяг бази й сховища) — цілком достатньо для
  однієї студії, але варто знати про це наперед.
- Адмін бачить учнів і чергу друку будь-якого викладача лише в режимі
  перегляду (без редагування) — навмисно, щоб не зіпсувати чужі дані.
  А розклад занять адмін якраз і повинен редагувати — це його основна
  робота в цій системі.
- При заміні чи видаленні фото старий файл у сховищі не видаляється
  автоматично («осиротілий» файл). Для невеликої студії це не критично,
  але з часом накопичується — можемо додати автоочищення пізніше, якщо
  знадобиться.
